# 05 우주 표류 — fiddle "오목 렌즈 배치"로 다시 만들기 (설계)

2026-11-24 · 사용자: "우리 우주표류 만든 거 여기 이걸로 수정해야 해" + 그리드 화면 스크린샷 "이 배치 · 약간 전체 오목 렌즈처럼 되는 저 배치".
선택: 가져올 범위 **배치 + 렌즈 + 움직임까지**, 겹치는 움직임은 **레퍼 움직임으로 교체**, 깊이는 **레퍼처럼 같은 거리**.

## 1. 레퍼런스

- https://exp.fiddle.digital/ (Fiddle.Digital Experiments Hub). 화면 폭 1024px 넘으면 위 LIST/GRID 버튼으로 그리드 보기.
- Nuxt + Three.js 182, 전체 화면 캔버스 하나. 실제 스크립트(`_nuxt/entry.*.js`, `useExperimentModal.*.js`)를 받아 원리와 숫자만 읽었다. 코드는 가져오지 않고 우리 식으로 다시 쓴다.
- 그리드 보기에서 본 것:
  1. **다이아몬드 배치**: 실험 카드 9장이 5×5 칸 중 9칸에 놓인다. 가운데 칸(2,2)은 비우고 로고.
  2. **화면 가장자리 오목 렌즈**: 카드는 평평하게 그리고, 다 그린 화면을 후처리(`LiquidGlassShader`)로 가장자리 띠에서만 휜다. 가장자리 카드가 늘어나며 굽고 무지개 테두리가 생김.
  3. **마우스 따라 밀리기**: 카드가 커서 반대쪽으로 밀린다. 가운데에서 먼 카드일수록 많이.
  4. **카드 면 일렁임**: 가만히 있어도 카드 면이 깊이 방향으로 아주 살짝 일렁인다.
  - 끌어도 그리드는 안 움직인다(끌기·휠은 LIST 보기 전용).

## 2. 레퍼에서 읽은 숫자

| 항목 | 값 |
|---|---|
| 그리드 칸 (x, y) | PXD VID (2,0) · CNVS BLR (3,0) · GRL FLX (1,1) · HP VLCT (4,1) · TT GRD (0,2) · 3D FLLS (3,2) · CSS BLR (1,3) · SQRLCS (4,3) · MTN CPTR (2,4) |
| 그리드가 차지하는 넓이 | 화면 폭 98% × 높이 82% (가운데 기준, 위아래 치우침 0) |
| 카드 폭 | 화면 폭의 13.5% × 크기 배율 (1 + (폭/1000 − 1) × −0.2) |
| 칸 간격 | 가로 한 칸 = 카드 폭 + ((98%폭 − 카드 폭)/4 − 카드 폭) × 가로 배율 (1 + (폭/1024 − 1) × −0.1, −100~100) · 세로 한 칸 = 카드 높이 + ((82%높이 − 카드 높이)/4 − 카드 높이) × 세로 배율 (1 + (높이/640 − 1) × −0.5, −1~0.5). 바깥 카드 가장자리까지 98%·82% 안에 들어가게 펼치고, 이웃 열은 반 칸씩 엇갈려 겹치지 않는다 |
| 렌즈 (데스크톱) | 유리 반경 0.35 (좌우는 ×1.6), 가장자리 여유 0.09, 굴절 1.3, 늘림 0.32, 색 번짐 0.004, 움직일 때 늘림 +0.2 |
| 렌즈 (폭 1024px 이하) | 위 값 전부 × 0.5 |
| 마우스 밀림 | 최대 −180px × 세기 2 (음수 = 커서 반대쪽), 가운데 거리 곡선 √(거리), 최소 영향 0.1, 따라가기·돌아오기 0.08 (60fps 한 프레임 기준) |
| 면 일렁임 | 깊이 0.2662 (레퍼 카드 폭 4.67 기준), 공간 배율 0.86, 시계 초당 0.16 (2π에서 되돌림), 가만히 있을 때 12% → 움직이면 100% |
| 움직임 세기 신호 | 데드존 0.45, 세제곱으로 올라감, 올라갈 때 8 · 내려갈 때 6 · 멈추면 16 (초당) |
| 등장 | 0.5배에서 3.6초 동안 커짐(easeInOutQuart), 카드는 0.3초 뒤부터 0.15초 간격으로 나타남 |

렌즈 원리 (화면 좌표 uv 0~1):
- 네 가장자리마다 `smoothstep(−여유, 반경, 가장자리까지 거리)`, 넷을 곱한 값이 1이면 가운데(그대로), `mask = 1 − 곱`.
- 그림을 가져올 자리 = `uv + (흐름 − 늘림) × mask`
  - 흐름 = −(가장자리 쪽 방향) × sin(mask·π) × 굴절 × 0.015
  - 늘림 = (uv − 0.5) × |uv − 0.5|² × 늘림 세기
- 색 번짐: 빨강은 가장자리 방향으로 조금 더, 파랑은 반대로 조금 덜 가져온다(반경·여유 절반 띠, 세기 × (0.35 + mask × 0.65)).

면 일렁임 원리 (카드 uv 0~1, 가운데 기준 p = uv − 0.5):
- 물결 A = sin(p·(3.1, 1.7)·0.86 + 시계 + 카드 씨앗), 물결 B = sin(p·(−1.35, 3.75)·0.86 − 시계×2 + 카드 씨앗×1.618)
- 높이 = (A×0.68 + B×0.32) × 가장자리 안정(테두리 16% 안쪽은 0.32배까지 줄임) × (1 − 0.3|p|²) × 깊이 × 움직임 가중(0.12~1)

## 3. 바뀌는 것

### 배치 (layout.js)
- 5장 우표 배치(`COMPOSITION`) → **다이아몬드 9칸** (`DIAMOND`, 위 표의 칸 그대로). 카드 수 기본 9 (패널 1~9).
- 칸 → 화면 위치: 2장 표의 레퍼 간격 식 그대로(가운데 칸이 화면 가운데). 카드 폭은 화면 폭 13.5% × 크기 배율.
- 카드는 우리 공통 종이 카드 그대로(비율 1.42, 둥근 모서리). 레퍼 카드(그리드에서 거의 정사각)보다 길쭉하지만 레퍼 간격 식 그대로도 안 겹친다. 1440×900: 카드 177×252px, 가로 한 칸 303px, 세로 한 칸 187px(세로 배율이 최대 0.5로 묶임), 같은 열 카드끼리 세로 틈 122px. 맨 위·맨 아래 카드는 화면 밖으로 약 49px 나가는데, 레퍼 화면도 위아래 카드가 가장자리에서 잘려 렌즈로 휘어 보인다.
- **폭 768px 이하(레퍼 그리드의 좁은 화면 기준점)**: 레퍼는 이 폭에서 그리드 대신 목록이라 카드 크기 숫자가 없다 → 우리가 정함: 카드 폭 = 화면 폭 17%. (13.5%면 폰에서 너무 작고, 20%면 같은 줄 옆 칸인 (2,0)·(3,0)이 2~4px 겹침.) 375×812: 카드 64×91px, 가로 한 칸 77px, 세로 한 칸 117px, 카드 사이 최소 틈 13px. 768×1024: 최소 틈 26px. 테스트로 확인.
- **깊이**: 모든 카드 같은 거리(16), 깊이 어둠(`depthDim`) 뺌. 깊이감은 별먼지 3겹 + 렌즈로.
- 기울기(`tilt`) 없음: 레퍼처럼 반듯하게.

### 렌즈 (새 파일 lens.js · lens-pass.js)
- 우리 셰이더로 다시 쓴 후처리 한 단계. 공통 `stage.addEffect`로 빛 번짐 다음, 마지막 출력 직전에 넣는다(순서: 그리기 → 빛 번짐 → 렌즈 → 출력).
- 값은 2장 표 그대로, 화면 폭 1024px 이하면 절반. 렌즈 늘림 = 0.32 + 움직임 세기 × 0.2.
- 움직임 세기: 스크롤 빠르기(화면/초)를 1.5화면/초를 1로 보고(우리가 정한 기준), 레퍼 방식(데드존 0.45, 세제곱, 올라갈 때 8 · 내려갈 때 6 · 멈추면 16)으로 0~1. 면 일렁임 가중에도 같이 쓴다.
- 패널 "렌즈" 폴더: 켜기, 유리 반경, 굴절, 늘림, 색 번짐.

### 움직임
- **등장** (둥실 우표 `settleIn` 대신): 묶음 전체가 화면 가운데 기준 0.5배 → 1배, 3.6초, easeInOutQuart. 카드는 가운데에 가까운 순서로 0.3초 뒤부터 0.15초 간격으로 바로 나타남.
- **마우스 밀림**: 2장 표의 식 그대로(커서 반대쪽, 가장자리 카드일수록 많이, 최대 360px). 모일수록 줄여서 더미는 가운데에. 터치는 안 함.
- **면 일렁임**: 05 전용 셰이더(`glint-material.js`)에서 카드 면 깊이를 2장 식대로. 깊이는 우리 카드 폭(1.6)에 맞춰 0.2662 × 1.6 / 4.67 ≈ 0.091. 모일 때(gather)는 줄여서 더미에선 0.
- **빠지는 것**: 둥실(`floatOffset`), 각도 흔들림(`wobbleAngles`), 카메라가 커서 쪽으로 옮겨가는 마우스 시점, 등장 `settleIn`·`cssEase`, 깊이 어둠. 패널의 "움직임" 폴더는 마우스 밀림 세기·면 일렁임 깊이로 바뀜.

## 4. 그대로 두는 것

검은 우주 배경, 별먼지 3겹(카메라가 안 움직이니 떠다니는 먼지로 깊이감), 글레어(빛 8자), 반짝이(기본 끔), 빛 번짐(기본 끔), 스크롤 모이기 → 한 장 → 물결 뒤집기 → 정리(공통 `stack-choreography`), 모이기 전반에 똑바로 세우기(기울기가 없어 사실상 그대로), 누르면 뒤집기, 공통 카드 재질·질감 패널.

## 6. 확인

- 원본과 우리 데모를 같은 크기(1440×900)로 띄워 카드 9장의 위치·크기, 가장자리 휨 정도를 화면으로 비교.
- 폰(375×812)에서 카드가 겹치지 않고 다 보이는지, 렌즈가 절반 세기인지.
- 스크롤 모이기 → 한 장 → 뒤집기 → 정리가 예전처럼 되는지, 모일 때 일렁임·밀림이 0이 되는지.
- 콘솔 에러 없음, 테스트 전부 통과.

## 7. 확인 뒤 바뀐 것 (사용자 피드백, 2026-11-24)

- "폰에서 레퍼도 저만했어?" → 확인: 레퍼는 폰에서 그리드 없이 세로 목록(카드 폭 약 57%). 사용자 선택 "마름모 유지, 카드 크게, 좀 잘려도 돼" → 768px 이하는 17% 마름모를 통째로 1.5배(`narrowZoom`), 바깥 열은 화면 밖으로.
- "정확히 마름모라 너무 반듯해, 흐트러뜨리고 정면 기준으로 약간 회전도, 폰·PC 둘 다" → `SCATTER`: 레퍼 grid.jitter 방식(카드별 사인 해시, 이웃 틈의 45% 안으로 제한, 기운 만큼 넓어진 폭 반영) + 화면 안 기울기 ±6° · 좌우 비틀기 ±10° · 위아래 ±6°. 레퍼 jitter는 0이라 세기는 우리가 정함(가로 카드 폭 ±25%, 세로 카드 높이 ±17.5%까지). 모이기 0~60%에 먼저 정면으로. 패널 "흐트러짐" 0~2.
- 캡션과 폰 맨 아래 카드가 겹치는 건 그대로 (사용자: "카드 움직임 보려고 만든 페이지라 상관없어").
- "별로 안 흐트러졌어" → 원인: 틈의 45% 안으로 묶어서 PC에서 ±45px뿐 + 왼쪽 두 장((1,1)·(1,3))이 같은 쪽으로 밀려 줄이 그대로. 사용자 선택 "안 겹치게 + 방향 섞기", "좀 더 자유분방해도 돼" → `SCATTER.offsets`(칸마다 손으로 정한 방향, 같은 열 이웃은 반대, 맨 바깥 열만 둘 다 안쪽, 카드 폭 ±45%·높이 ±40%, 기울기 ±8°) + 겹치는 쌍만 칸 쪽으로 10%씩 되돌리기(분리축 틈 6px 또는 카드 폭 4% 이상). 비틀기 좌우 ±12°·위아래 ±8°. 1440×900에서 카드마다 55~110px 어긋남(전 ±45px). layout v17, main v21, 테스트 184.
