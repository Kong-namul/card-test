# 카드 UI 아카이브 — 1차: 3D 카드 데모 설계

- 날짜: 2026-11-20
- 상태: 설계 확정 대기 (사용자 리뷰 전)

## 1. 목표

멋진 카드 UI를 찾아서 **직접 웹에 구현해 두는 아카이브**. 나중에 다른 프로젝트에 가져다 쓰는 게 목적이다.

- 1차 범위: **3D 공간형 카드 5종** (나선, 구, 터널, 플로팅 필드, 우주 표류)
- 우선순위: **간지(완성도) > 개수**. 한 번에 하나씩 끝까지 다듬는다.
- 공부용: 코드에 **한국어 주석**을 자세히 단다.

### 성공 기준

- 데모마다 Grail(grail-app.com) 수준의 질감과 움직임: 휨, 깊이 어둠, 쫀득한 관성, 마우스 반응, 광택이 살아 있다.
- 데모마다 조절 패널이 있고, 마음에 드는 값을 "설정 복사"로 한 번에 복사할 수 있다.
- 데모 폴더 하나와 `shared/` 폴더만 복사하면 다른 프로젝트에서 그대로 동작한다.

### 1차에서 하지 않는 것

- 3D 외 계열(스크롤 스택, 포인터 반응, 스와이프, 플립·확장, 무한 갤러리)은 2차 이후로 미룬다.
- 카드 안의 글자나 이미지 콘텐츠는 넣지 않는다. 카드는 **무지**다.
- 여러 데모의 효과를 한 화면에서 섞는 "조합 실험실"은 만들지 않는다.

## 2. 레퍼런스 분석: Grail에서 배운 것

grail-app.com 메인의 나선 카드 섹션을 공부 목적으로 분석했다. 기술 구성은 Three.js(WebGL2), 직접 작성한 셰이더, Lenis 스크롤, React다.
**Grail 코드는 복사하지 않는다.** 아래 기법만 참고해서 우리 방식으로 다시 구현한다.

| 기법 | 설명 | 우리 적용 |
|---|---|---|
| 휜 카드 | 평면의 양옆 가장자리를 뒤로 말고(x² 곡률) 세로로도 살짝 휨 | 카드 지오메트리 정점을 휘게 만든다. 휨 때문에 광택이 카드 표면을 따라 흐른다. |
| 깊이 어둠 | 진짜 그림자 대신, 뒤쪽 카드를 최대 약 70%까지 어둡게 칠함 | 카드별 밝기 배율(instance color)로 구현한다. |
| 속도 잔상 | 회전 속도만큼 텍스처를 진행 방향으로 번지게 함 | 무지 카드라 텍스처 번짐은 안 보인다. 대신 잔상 후처리(AfterimagePass)의 세기를 속도에 연동한다. |
| 쫀득한 관성 | 목표값을 매 프레임 일정 비율로 따라감(lerp), 속도는 평균내서 튀지 않게 | `shared/motion.js`의 공통 함수로 만든다. |
| 납작한 나선 | 원 대신 깊이를 눌러 타원으로, 카드마다 일정 각도와 높이를 더함 | 01 나선의 기본 배치. |
| 마우스 반응 | 전체가 커서 쪽으로 살짝 기울고, 커서 근처 카드가 자석처럼 끌려옴 | 공통 함수로 만들고 데모마다 세기를 조절한다. |
| 망원 카메라 | 화각 38°로 좁게 잡아 왜곡을 줄이고 고급스럽게 | 모든 데모의 기본 화각을 좁게 잡는다. |
| 등장 연출 | 큰 반지름에서 시작해 오므라들며 등장 | 01 나선에 적용한다. |
| 물결 뒤집기 | 카드 윗부분이 먼저 돌고 아랫부분이 따라오며 360° 회전 | 01 나선에서 카드 클릭 시 적용한다. |

## 3. 기술 결정

- **3D**: Three.js. CDN에서 importmap으로 불러오고, 구현을 시작할 때 최신 안정 버전을 확인해 **정확한 버전 번호로 고정**한다.
- **빌드 도구 없음**: 순수 HTML + CSS + ES 모듈 JS. React도 쓰지 않는다.
- **조절 패널**: lil-gui(Three.js 애드온에 포함돼 있어 추가 의존성이 없다).
- **후처리**: Three.js 애드온의 EffectComposer, AfterimagePass(잔상), UnrealBloomPass(빛 번짐), BokehPass(초점 흐림)를 데모별로 필요한 것만 쓴다.
- **실행**: ES 모듈 구조상 `file://`로는 열리지 않는다. 로컬 서버로 연다(`python3 -m http.server`, `.claude/launch.json`에 등록해서 앱 안 브라우저로 미리보기).

## 4. 폴더 구조

```
card/
├─ index.html              ← 아카이브 첫 화면 (데모 5개 목록)
├─ shared/
│  ├─ tokens.css           ← 색·폰트 공통 파일 (SSOT)
│  ├─ base.css             ← 데모 페이지 공통 레이아웃 (전체화면 캔버스, 노트 영역)
│  ├─ stage.js             ← 렌더러·카메라·조명 환경·리사이즈·후처리 기본 세팅
│  ├─ card-material.js     ← 카드 재질 + 질감 프리셋 5종
│  ├─ card-geometry.js     ← 휜 카드 지오메트리 생성
│  ├─ motion.js            ← 관성, 마우스 기울기, 자석, 깊이 어둠 계산
│  └─ panel.js             ← lil-gui 래퍼 + "설정 복사" / "기본값으로" 버튼
├─ demos/
│  ├─ 01-spiral/index.html (+ main.js)
│  ├─ 02-sphere/
│  ├─ 03-tunnel/
│  ├─ 04-floating/
│  └─ 05-cosmos/
└─ docs/superpowers/specs/  ← 설계 문서
```

각 공통 부품은 하나의 역할만 맡고, 데모의 `main.js`는 "배치와 움직임"만 담당한다.
공통 CSS나 JS를 수정하면 데모 HTML에서 불러오는 주소의 `?v=` 버전을 올린다.

## 5. 디자인 토큰 (`shared/tokens.css`, SSOT)

사용자 승인: card 전용 공통 파일을 새로 만든다. 등록하는 값은 아래가 전부이고, 페이지에 색이나 크기를 직접 적지 않는다. 여기 없는 값이 필요해지면 먼저 물어본 뒤 추가한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-1` | `#0B0B0C` | 페이지·3D 장면 배경 |
| `--bg-2` | `#161618` | 노트 영역, 목록 카드 배경 |
| `--card-paper` | `#F4F1EA` | 무지 카드 기본색 (오프화이트) |
| `--fg-1` | `#FFFFFF` | 제목, 본문 강조 |
| `--fg-2` | `rgba(255,255,255,0.64)` | 본문 |
| `--fg-3` | `rgba(255,255,255,0.40)` | 캡션, 메타 정보 |
| `--border` | `rgba(255,255,255,0.12)` | 구분선 |
| `--font-body` | `'Pretendard Variable', Pretendard, -apple-system, sans-serif` | 모든 글자 |
| `--text-72 / 48 / 32 / 24 / 22 / 18 / 14` | 72·48·32·24·22·18·14px | 글자 크기 (이 스케일만 사용) |
| `--lh-72 / 48 / 32 / 24 / 22 / 18 / 14` | 88·58·40·32·32·28·20px | 각 크기의 줄 간격 |

- 제목은 단색(흰색)만 쓴다. 보라 같은 포인트 색은 넣지 않는다.
- Pretendard는 jsDelivr CDN에서 버전을 고정해 불러온다.
- 3D 장면 배경색과 카드 기본색은 JS에서 CSS 변수(`getComputedStyle`)로 읽어 쓴다. JS에 색을 하드코딩하지 않는다.

## 6. 카드 재질과 질감 프리셋 (`shared/card-material.js`)

Three.js의 `MeshPhysicalMaterial`에 조명 환경(RoomEnvironment)을 비춰 실제 같은 반사를 만든다. 카드는 앞뒤 모두 무지다.

| 프리셋 | 느낌 | 주요 설정 |
|---|---|---|
| 무광 종이 | 빛 반사가 거의 없는 종이 | roughness 높음, clearcoat 0 |
| 유광 코팅 | 투명 코팅층이 한 겹 올라간 종이. 돌 때 빛줄기가 지나감 | clearcoat 1, clearcoatRoughness 낮음 |
| **홀로그램 박 (기본값)** | 유광 + 보는 각도에 따라 은은한 무지개빛 | clearcoat 1 + iridescence |
| 금박 | 금속 반사, 따뜻한 색 | metalness 높음, 금색 |
| 은박 | 금속 반사, 차가운 색 | metalness 높음, 은색 |

- 패널에서 프리셋을 고른 뒤 광택 세기(clearcoat), 거칠기(roughness), 무지개 세기(iridescence)를 슬라이더로 다시 조절할 수 있다.
- 금·은 색은 재질 설정값이다. 페이지 UI 색이 아니므로 토큰이 아니라 `card-material.js` 안의 프리셋 표 한곳에만 둔다.
- 깊이 어둠은 카드별 밝기 배율(InstancedMesh의 instance color)로 적용한다.

## 7. 데모 페이지 공통 구성

- 화면 전체: 3D 장면
- 오른쪽 위: 조절 패널 (접기 가능)
  - 공통 항목: 질감 프리셋, 광택, 거칠기, 무지개 세기, 카드 색, 휨
  - 데모별 항목: 아래 8장 참고
  - 버튼: **설정 복사**(현재 값을 JSON으로 클립보드에 복사), **설정 붙여넣기**(복사해 둔 JSON을 넣으면 그 값으로 바뀜), **기본값으로**
- 왼쪽 아래: 데모 이름, 한 줄 설명, 조작법(스크롤, 드래그, 마우스)
- 스크롤 아래 노트 영역: 이 데모에 쓴 기법 설명(한국어)과 참고한 원본 사이트 링크

## 8. 데모 5종 상세

### 01. 나선 (Grail식) — 가장 먼저 만든다

- 배치: 납작한 나선. 세로 간격이 0이면 링이 된다.
- 움직임: 자동으로 천천히 흐르고, 휠과 드래그로 감는다. 쫀득한 관성.
- 처리: 휨, 깊이 어둠, 속도 잔상, 마우스 기울기, 자석, 등장 연출, 카드 클릭 시 물결 뒤집기.
- 패널: 감기 정도, 반지름, 납작함, 세로 간격, 가장자리 기울기, 카드 크기, 카드 수, 자석, 마우스 기울기, 자동 속도, 잔상 세기.

### 02. 구

- 배치: 피보나치 구 배치로 카드가 공 표면을 고르게 덮는다. 휜 카드가 공 곡면을 따라간다.
- 움직임: 드래그로 돌리고, 놓으면 관성으로 돌다 서서히 멈춘다. 가만두면 아주 천천히 자전한다.
- 처리: 뒤쪽 카드는 깊이 어둠으로 어둡게, 커서 아래 카드는 바깥으로 살짝 떠오른다.
- 패널: 반지름, 카드 수, 카드 크기, 자전 속도, 관성 세기, 떠오름 세기.

### 03. 터널

- 배치: 원통 안쪽 벽에 카드가 줄지어 붙는다.
- 움직임: 휠로 터널 안을 전진하고, 끝없이 반복된다.
- 처리: 먼 곳은 안개(scene fog)로 사라지고, 카드가 옆을 스칠 때 광택이 번쩍인다. 빨리 갈수록 터널이 살짝 비틀린다.
- 패널: 전진 속도, 터널 반지름, 카드 밀도, 비틀림, 안개 거리.

### 04. 플로팅 필드

- 레퍼런스(사용자 선택 "①+② 섞기"): 뼈대는 Codrops "Infinite Canvas"(Edoardo Lunardi, MIT, 코드 공부용), 아이디어는 Framer "Depth Drift Gallery"(Konstantin Nikolaev, 유료라 코드 X: 먼 층일수록 느리고 작고 흐릿, 진행 방향으로 카드가 기울어짐).
- 단위: 레퍼런스 숫자 ÷ 10 (공통 카메라 far 200 안에 들어오게). 아래 괄호는 레퍼 원래 값.
- 배치: 11(110) 크기 칸마다 카드 5장 밀도로 공간에 고르게 흩뿌림(고정 시드). 카드 높이 1.2~2.0(12~20), 화각 60°, 카드는 카메라를 정면으로 봄.
- 끝없는 공간: 레퍼는 칸을 만들었다 지웠다 하지만, 우리 카드는 무지라 다 똑같이 생겨서 카메라 주변 상자 밖으로 나간 카드를 반대편으로 접는다(03 터널 `wrapCentered` 방식, 공통 motion.js로 옮김). 상자 크기는 사라지는 거리와 화면비 2.4까지 덮도록 계산, 상자 가장자리 근처 카드는 작아지며 사라짐.
- 움직임: 드래그 1px = 0.0025(0.025), 터치 0.002(0.02), 휠 1px = 0.0006(0.006)을 목표 속도에 쌓고(남은 양은 프레임당 0.8배), 목표 속도 상한 0.32(3.2), 실제 속도는 프레임당 16%씩 따라가고 목표 속도는 0.9배씩 줄어듦(관성). 휠 아래 = 앞으로 파고들기. 두 손가락 벌리기 = 앞뒤. 프레임레이트 보정(60fps 기준).
- 마우스 시점: 커서 쪽으로 카메라가 최대 0.8(8) 옮겨감(프레임당 12%), 드래그 중엔 멈춤.
- 먼 카드: 안개(배경색 --bg-1)로 12부터 흐려지기 시작해 26에서 완전히 사라짐 (레퍼: 안개 120~320 + 투명도 140~260을 합친 느낌).
- 섞는 것: 카드별 초점 흐림(초점 거리 7. BokehPass는 배경까지 흐려서 또렷한 카드 주변에도 빛번짐이 생겨서, 무지 카드에 맞게 카드마다 둥근 가장자리를 |거리 − 초점|에 비례해 퍼뜨림 → 공통 재질에 `instanceSoft` 추가, 투명 + 먼 카드부터 정렬해 그림), 진행 방향으로 카드 기울기, 카드마다 다른 박자로 둥실둥실, 누르면 뒤집기(01~03 공통).
- 패널: 질감(+휨) / 공간(카드 밀도, 카드 크기, 사라지기 시작·끝) / 움직임(드래그·휠 감도, 따라가기, 관성, 마우스 시점 세기, 둥실 세기, 기울기 세기) / 초점 흐림(켜기, 초점 거리, 흐림 세기).

### 05. 우주 표류

- 레퍼런스: "카드가 우주를 떠다니는 장면" 자체는 마땅한 레퍼가 없어서 장면은 우리 계획대로. 반짝임 기법만 원리 공부(코드 X): 포켓몬 홀로 카드 CSS(Simon Goellner, GPL — 커서 따라 지나가는 글레어), 포일 스티커 셰이더(4rknova, 모든 권리 보유 — 칸마다 법선을 비튼 반짝이 알갱이), Ziggy 카드(Isaac Johnson — MeshPhysicalMaterial에 셰이더를 덧붙여 각도별 반짝임). 사용자 선택: "글레어 + 반짝이 섞기".
- 04와의 차이: 04는 끌고 헤엄치는 장면, 05는 가만히 바라보는 장면(카메라는 마우스 따라 살짝만).
- 배치: 카드 26장을 화면 좌표(−1~1)·깊이 비율(0~1)로 고정 시드 배치 → 그릴 때 화면비에 맞춰 공간 좌표로(거리 7~26, 화각 40°). 폰이든 와이드든 화면 전체에 고르게, 화면을 돌려도 재배치 X. 04처럼 겹침 방지 간격. 카드 높이 1.6~2.6, 처음 방향 ±25°·±15°·±8°(카드마다 빛 받는 순간이 다르게).
- 움직임: 둥실(위아래 0.18·좌우 0.08, 14~24초), 각도 흔들림(최대 12°, 9~17초), 먼 카드일수록 어둡게(최소 0.45), 마우스 시점, 누르면 뒤집기.
- 반짝임: 보이지 않는 빛이 카메라 앞 반구에서 8자로 18초에 한 바퀴 훑는다. 글레어 = (빛·카메라 중간 방향 · 법선)^60, 반짝이 = 카드 표면 40칸/단위 중 12% 칸에 법선을 비튼 알갱이, (…)^300으로 각도 맞는 것만 + 깜빡임, 글레어 근처에서만. 둘 다 1보다 밝게 더해서 빛 번짐(UnrealBloomPass, 문턱 1)이 번쩍이는 부분만 잡음. 공통 카드 재질은 그대로, 05 전용 `glint-material.js`가 셰이더를 덧붙임.
- 별먼지: 1,800개 점을 카드 뒤(거리 28~88)에 흩뿌리고 각자 다른 박자로 깜빡임(색 --fg-1).
- 패널: 질감(+휨) / 공간(카드 수, 배치 번호, 카드 크기) / 움직임(떠다니는 속도, 둥실 폭, 흔들림 각도, 마우스 시점) / 반짝임(빛 한 바퀴, 글레어 세기·날카로움, 반짝이 양·세기) / 빛 번짐(세기, 퍼짐, 문턱) / 별(개수, 깜빡임).

## 10. 성능과 예외 처리

- 픽셀 비율 상한: 데스크톱 2, 모바일 1.5.
- 탭이 안 보일 때는 렌더링을 멈춘다(requestAnimationFrame 기본 동작).
- WebGL을 쓸 수 없으면 캔버스 대신 "이 브라우저에선 3D를 볼 수 없어요" 안내를 띄운다.
- `prefers-reduced-motion`이 켜져 있으면 자동 회전과 표류를 끄고, 사용자가 직접 조작할 때만 움직인다.
- 화면 크기가 바뀌면 카메라 비율과 렌더러 크기를 다시 맞춘다.

## 11. 코드 주석 규칙

- 공부용이다. 함수와 주요 계산마다 **무엇을 하는지, 왜 이 숫자인지**를 한국어로 적는다.
- 수학(삼각함수, 보간 등)은 "이 줄이 화면에서 어떤 변화를 만드는지" 위주로 설명한다.

## 12. 검증 방법

데모 하나를 완성할 때마다:

1. 로컬 서버로 열고 앱 안 브라우저로 스크린샷을 찍어 확인한다.
2. 콘솔 에러가 0개다.
3. 패널의 모든 항목이 화면에 반영되고, 설정 복사로 나온 JSON을 설정 붙여넣기로 다시 넣으면 같은 화면이 된다.
4. 375px 모바일 폭에서도 깨지지 않는다(터치 드래그 동작 포함).
5. 사용자가 보고 "개멋짐" 판정을 해야 다음 데모로 넘어간다.

  - **2차 피드백 (사용자)**: "1번은 궁둥이가 보여서 별로, 45°로 돌려줘 / 3번은 뒤집혀 있어". → 튜브를 따라 계속 돌던 방향을 고정 + 살랑살랑(±0.12rad)으로 바꾸고, 모델별 기본 방향 `viewYaw` 추가. 화면에서 0/90/180/-90°를 찍어 재보니 모나크는 0°=엉덩이, 180°=정면 → 기본 135°(정면에서 45°). 각진 크리스탈은 세우는 각도 부호를 −1.2로 뒤집음. 패널에 "방향 조절 (도)" 슬라이더.
