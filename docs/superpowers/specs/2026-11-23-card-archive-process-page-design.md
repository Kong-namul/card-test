# 작업 방식 페이지 — 설계

2026-11-23 · 사용자 요청: "너가 지금 하는 작업방식? 배포사이트에 정리해서 넣어줄 수 있어?" → 구성안 A/B/C 중 **A(한 페이지 정리)** 선택.

## 목적

이 아카이브의 카드 데모를 어떻게 만드는지(과정·막혔을 때 푸는 법·지키는 약속)를 배포 사이트에 한 페이지로 남긴다.
나중에 다시 볼 때, 또 다른 세션과 일할 때 같은 방식으로 일하게 하는 기준이 된다.

## 위치

- 파일: `process/index.html` → https://kong-namul.github.io/card-test/process/
- 아카이브 첫 화면 소개 문구 옆에 알약 라인 버튼 "작업 방식 →".
- 페이지 왼쪽 위에는 데모 페이지와 같은 "← 아카이브" 링크.

## 모양 (공통 파일만)

- `shared/tokens.css`, `shared/base.css`만 쓴다. 새 색·새 글자 크기 없음.
- 본문 틀은 데모 노트와 같은 `.notes`(최대 720px) + `h1`(48) · `h2`(24) · `dl/dt/dd`(18).
- 제목은 흰색 단색. 보라 같은 강조색 안 씀.
- `base.css`에 추가하는 것은 두 가지뿐. 공통 CSS를 고치므로 모든 페이지의 `base.css?v=4 → v=5`.
  - 첫 화면 링크는 소개 문구 바로 옆 알약 라인 버튼 (사용자 요청). 데모 캡션의 "기법 노트 ↓"(`.notes-jump`) 모양을 공통 `.pill-link`로 빼서 같이 쓴다 (모양 값은 그대로: 1px `--border` 테두리, 999px 둥글기, 8·16px 안쪽 여백, 14px `--fg-2`). `.archive-intro`는 한 줄 배치(flex, 좁으면 버튼이 아래 줄로).
  - `.back-link.is-static`: 이 페이지의 "← 아카이브"는 고정하지 않고 맨 위에만 (확인 중 발견: 고정이면 폰에서 스크롤한 본문 위에 겹침). 데모 페이지는 그대로 고정.

## 구성 (A)

1. **머리말** — 제목 "작업 방식", 한두 줄 소개 (Claude Code와 같이 만든다, 고르는 건 사람).
2. **카드 하나 만드는 8단계** — 단계마다 무엇을 하는지 + 실제 있었던 예 한 줄.
   1. 진짜 레퍼 찾기 · 2. 고르기 · 3. 원본 뜯어보기 · 4. 설계 승인 · 5. 테스트 먼저 · 6. 공통 부품으로 만들기 · 7. 원본과 나란히 실측 · 8. 확정·배포
3. **막혔을 때 고치는 법** — 원칙(원인부터 숫자로 · 한 번에 하나 · 전·후 같은 조건으로 재기 · 세 번 안 되면 방향 의심 · 사람 손 안 닿는 측정 · 끝까지 직접 보기) + 사례 "02 구 180° 뒤집힘"(문제 → 원인 → 첫 시도 실패 → 띠 → 결과 숫자).
4. **이렇게 말해주면 빨라** — 막혔을 때 사람이 해주면 좋은 말 (원인부터 숫자로 보여줘 / 세 번 안 되면 방향 바꾸자 / 스크린샷 + 어느 순간인지).
5. **지키는 약속** — 코드는 복사 없이 원리만 · 공통 파일만(없으면 먼저 묻기) · 추측 대신 실측 · 고르는 건 사람 · 커밋·배포는 말할 때만.

## 사실 확인한 숫자 (페이지에 쓰는 것)

- 02 180° 뒤집힘: 반쯤 모인 채 빠르게 돌려 12초 측정, 고치기 전 배포본 36번 → 고친 뒤 0번.
- 02 오래 두기: 기본 속도 3바퀴씩 계산, 뒤집힘 0. 혼자 도는 뒤 카드는 그 카드만 숨겨 픽셀 비교 → 0픽셀(맨 앞 카드 숨기면 23%).
- 02 마지막 장면: 도는 걸 모이기 85%에서 끝내서 비스듬한 카드 0.
- 10 휘어진 호: 카드 8장 → 원본처럼 6장으로 맞추니 일치. 원본은 시간 보정 없이 프레임마다 따라가서 그 방식 그대로.
- 테스트: 전체 176개 통과 (02 모이기 계산 16개).
